# دليل التفعيل والتشغيل والاستخدام — TOSO

دليل واحد بالتسلسل الذي تمشي عليه من جهاز نظيف حتى أول رد من وكيل CLI.

**الخلاصة في أربعة أسطر**

1. ثبّت المتطلبات وشغّل `npm install` ثم `npm run dev:all`.
2. افتح «الإعدادات» وأضف مفتاحك (أو مفتاح الخادم) ثم اختر الوكيل الافتراضي.
3. ثبّت وكيل CLI واحداً على الأقل وسجّل دخولك إليه.
4. في القسم 04: مجلد المشروع ← ① فحص ← ② و③ اختياريان ← ④ تشغيل الجلسة، ثم أرسل.

---

## 1. المتطلبات

| المتطلب                 | التفاصيل                                                                                                |
| ----------------------- | ------------------------------------------------------------------------------------------------------- |
| Node.js                 | 22.12 أو أحدث                                                                                           |
| نظام التشغيل            | Windows وmacOS جاهزان للطرفيات المدمجة (`node-pty` بملفات جاهزة). Linux يحتاج أدوات بناء — انظر القسم 8 |
| مفتاح Gemini            | اختياري. بدونه تعمل التنقية العربية محلياً فقط، ولا تتاح الترجمة الإنجليزية                             |
| وكيل CLI واحد على الأقل | لإرسال النص المنقّح واستقبال النتيجة — انظر القسم 4                                                     |

## 2. التثبيت

```bash
npm install
```

### مفتاح الخادم (اختياري)

أنشئ `.env.local` في جذر المشروع:

```env
AGENT_PLATFORM_API_KEY=مفتاحك
```

- يُقرأ في الخادم فقط ولا يصل للمتصفح.
- لا حاجة له إن كنت ستستخدم مفتاحك الشخصي من الإعدادات (القسم 5).
- إن كان عندك متغير بيئة نظام قديم بالاسم نفسه فسيحجب الملف — انظر القسم 8.

## 3. التشغيل

```bash
npm run dev:all
```

يشغّل التطبيق (`http://localhost:3000`) والجسر المحلي (`127.0.0.1:8676`) معاً، ويفتح المتصفح، ويقرن التطبيق بالجسر تلقائياً — لا نسخ للتوكن. `Ctrl+C` يوقف الاثنين.

| الأمر                          | متى                                    |
| ------------------------------ | -------------------------------------- |
| `npm run dev:all`              | الطريقة الموصى بها                     |
| `npm run dev`                  | التطبيق وحده (بلا إرسال للوكلاء)       |
| `npm run bridge`               | الجسر وحده، إن كان التطبيق يعمل مسبقاً |
| `npm run build` ثم `npm start` | نسخة الإنتاج                           |

إن كان المنفذ `8676` مشغولاً بجسر يعمل، يعيد `dev:all` استخدامه بدل تشغيل جسر ثانٍ.

## 4. تثبيت وكلاء CLI وتسجيل الدخول

الشرط الوحيد: أن يكون أمر الوكيل في `PATH`. طريقة التثبيت لا تهم.

| الوكيل      | الأمر                                                                               | تسجيل الدخول                                                |
| ----------- | ----------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| Gemini CLI  | `npm i -g @google/gemini-cli`                                                       | مفتاح API (تسجيل الدخول بحساب Google الشخصي لم يعد مدعوماً) |
| Claude Code | `irm https://claude.ai/install.ps1 \| iex` أو `winget install Anthropic.ClaudeCode` | شغّل `claude` ثم `/login`                                   |
| Codex       | `npm i -g @openai/codex`                                                            | `codex login`                                               |
| Devin       | مثبّته الرسمي                                                                       | `devin auth login`                                          |
| Hermes      | مثبّته الرسمي                                                                       | إعداد مزوّد النموذج                                         |

**قبل المتابعة** سجّل دخولك لكل وكيل **مرة واحدة من طرفيتك العادية** (شغّل أمره وأكمل الدخول). إن لم تفعل، سيعرض TOSO رسالة الوكيل الحقيقية مثل `Not logged in` بدل أن يخفيها.

للتحقق من أن الأوامر مرئية (PowerShell):

```powershell
Get-Command gemini, claude, codex, devin, hermes -ErrorAction SilentlyContinue
```

> **أعد تشغيل `npm run dev:all` بعد تثبيت أي وكيل جديد.** الجسر يأخذ نسخة من `PATH` لحظة تشغيله فلا يرى ما ثُبّت بعده.

وكيل مثبّت خارج `PATH`؟ عيّن مساره بمتغير بيئة قبل تشغيل الجسر: `TOSO_AGENT_CMD_<ID>` (مثل `TOSO_AGENT_CMD_CLAUDE`).

## 5. الإعدادات الأولية

افتح الزر **«الإعدادات»** أعلى الصفحة. الأقسام الأربعة بترتيبها:

### المفتاح والوصول

- ضع مفتاح AI Studio الخاص بك (يُحفظ في متصفحك فقط) **أو** اتركه فارغاً لاستخدام مفتاح الخادم.
- لا مفتاح على الإطلاق = الوضع المحلي (عربي فقط).

### النموذج

- اختر نموذج Gemini.
- زر **«تحقق من النماذج»** يفحص النماذج المتاحة لمفتاحك فعلاً (عبر `countTokens`، بلا تكلفة توليد). النموذج غير المتاح يُعلَّم «غير متاح» في القائمة.

### جسر وكيل CLI

- **عنوان الجسر والتوكن:** لا تلمسهما إن كان الجسر على جهازك بالإعدادات الافتراضية؛ القيم المكتشفة تظهر رمادية. اكتبهما بنفسك فقط إن غيّرت المنفذ أو التوكن.
- **الوكيل الافتراضي:** الوكيل الذي يستقبل النص عند الإرسال التلقائي.
- **إرسال تلقائي إلى الوكيل الافتراضي:** إن فُعّل، يُرسَل الناتج الأساسي تلقائياً بعد كل تحليل (انظر القسم 7).

### ردود الوكيل (تبويب OUT)

- **ترجمة تلقائية لكل رد:** مفعّل = يظهر كل رد بالعربية فور التقاطه؛ معطّل = زر «ترجمة» بجانب كل رد.
- **تنظيف ذكي للمخرجات عبر Gemini:** مرور ثانٍ اختياري على ما التُقط من شاشة الطرفية، ولا يُقبل ناتجه إلا إن كان مبنياً على النص الملتقط نفسه.

> إعدادات الثقة والمجلد **ليست هنا** — هي لكل وكيل في تبويبه (القسم 6).

## 6. إعداد كل وكيل (القسم 04 في الصفحة)

لكل وكيل تبويب. اختر تبويبه ثم أدخل مسار مجلد المشروع **الذي يجب أن يعمل عليه**، ثم امشِ على الخطوات بالترتيب:

| الخطوة | الاسم          | إلزامية؟       | ماذا تفعل                                                     |
| ------ | -------------- | -------------- | ------------------------------------------------------------- |
| ①      | فحص المجلد     | **إلزامية**    | تتأكد أن المجلد موجود. **تفتح بقية الخطوات.**                 |
| ②      | ثقة دائمة      | اختيارية       | تسجّل المجلد موثوقاً في ملف إعدادات الوكيل نفسه               |
| ③      | ثقة لكل تشغيلة | اختيارية       | مفتاح مؤقت يُزرع في عملية الوكيل ويموت معها، بلا كتابة أي ملف |
| ④      | تشغيل الجلسة   | الخطوة الأخيرة | تشغّل واجهة الوكيل التفاعلية داخل المجلد المفحوص              |

كل نجاح يتحول للأخضر. نتيجة ① و② مرتبطة بالمجلد الذي نجحت عليه: **غيّر المسار فتُقفل الخطوات من جديد.**

### شارات القدرة على ② و③

| الشارة             | المعنى                                                               |
| ------------------ | -------------------------------------------------------------------- |
| **مدعوم**          | TOSO يتحكم بالخطوة — تُفتح بعد ①                                     |
| **مدعوم تلقائياً** | الوكيل لا يسأل عن ثقة المجلد أصلاً — خضراء من البداية، لا شيء لتفعله |
| **غير مربوط**      | الوكيل يملك الآلية ولم تُربط بـTOSO بعد                              |
| **غير مدعوم**      | الوكيل يسأل عن الثقة لكن لا يملك هذه الآلية — أجب سؤاله داخل الطرفية |

### حالة كل وكيل اليوم

| الوكيل       | ② ثقة دائمة    | ③ ثقة لكل تشغيلة |
| ------------ | -------------- | ---------------- |
| Gemini CLI   | مدعوم          | مدعوم            |
| Devin        | مدعوم          | غير مدعوم        |
| Claude Code  | مدعوم          | غير مدعوم        |
| OpenAI Codex | مدعوم          | غير مدعوم        |
| Hermes       | مدعوم تلقائياً | مدعوم تلقائياً   |

### ملاحظات مهمة

- **ثقة دائمة (②) تغيّر ملف إعدادات الوكيل نفسه**، فيشمل أثرها جلساتك اليدوية خارج TOSO أيضاً. الكتابة تضيف هذا المجلد فقط وتحفظ بقية محتويات الملف.
- لا يعمل أي وكيل من TOSO قبل نجاح ①: الإرسال والجلسة والنافذة الخارجية كلها ترفض مع رسالة داخل تبويب الوكيل.
- لا تبدأ الجلسة وحدها عند فتح التبويب: تبدأ بزر ④ أو عند أول إرسال.
- **أسئلة الأذونات** (مثل «Allow execution of…» أو «هل تثق بهذا المجلد؟») يجيبها المستخدم **داخل الطرفية المدمجة**. TOSO لا يعتبر السؤال رداً: يعرض «الوكيل ينتظر قراراً منك في الطرفية أعلاه — أجب عليه ثم أعد الإرسال». أجب في الطرفية ثم أرسل مجدداً.
- زر **«أو افتح نافذة خارجية منفصلة»** يفتح نافذة PowerShell مستقلة لا يقرؤها TOSO ولا تشارك سياق الطرفية المدمجة.

## 7. الاستخدام بالتسلسل

1. **اكتب التلقينة** في القسم 01 ثم اضغط **«تشغيل التحليل»**.
2. **راقب القسم 02**: قياس الـTokens ثم التنقية وإعادة الصياغة.
3. **اقرأ القسم 03**: نسخة عربية منقّحة ونسخة إنجليزية، مع تقرير التوفير وفحص الكيانات.
4. **جهّز الوكيل في القسم 04** (مرة لكل وكيل ولكل مجلد): تبويب الوكيل ← المسار ← ① ← (② و③ إن أردت) ← ④.
5. **أرسل النص** من بطاقة المخرجات:
   - زر **«الوكيل ▾»** لاختيار الوكيل فقط — **لا يرسل شيئاً**.
   - الزر الذي يحمل **اسم الوكيل** هو الذي يرسل.
   - **الإرسال من البطاقة الإنجليزية فقط**: الوكلاء يستقبلون الإنجليزية دائماً لتقليل التوكنز، حتى لو كتبت بالعربية، وبطاقة العربية للقراءة والنسخ فقط. إن لم تتوفر نسخة إنجليزية (الوضع المحلي) لا يُرسل شيء وتظهر رسالة توضح السبب.
6. **اقرأ النتيجة** في تبويبي **IN** و**OUT** لكل دورة: النص المرسل والرد الملتقط، والعربية بجانب الإنجليزية، مع ترجمة الرد.

### وضعا الإرسال

| الحالة                             | سلوك زر اسم الوكيل                                             |
| ---------------------------------- | -------------------------------------------------------------- |
| الإرسال التلقائي معطّل             | يدوي دائماً — يرسل عند الضغط                                   |
| مفعّل والوكيل المختار هو الافتراضي | **معطّل وظاهر** بشارة «تلقائي»، والإرسال يتم وحده بعد كل تحليل |
| مفعّل واخترت وكيلاً آخر            | يتحرر الزر ويصبح الإرسال يدوياً                                |
| أعدت اختيار الافتراضي              | يتعطل الزر ويعود كل شيء تلقائياً                               |

### مرجع الرد

- إن كانت الطرفية المدمجة غير متاحة (بلا `node-pty`) يسقط الجسر إلى تشغيل أحادي: `gemini -p` / `devin -p --prompt-file` / `hermes --oneshot` / `claude -p` / `codex exec`.
- زر **«التقط الآن»** يظهر أثناء الدورة لإنهائها يدوياً إن طال الانتظار.
- إن رأيت في OUT نصاً غير مرغوب من واجهة وكيل، افتح قسم `raw capture` في بطاقة الرد (النص الخام كما التُقط من الشاشة) وأرسله للمطوّر مع اسم الوكيل ليُضاف نمطه.

## 9. الأمان في سطرين

- الجسر يستمع على `127.0.0.1` فقط، وكل طلب يحتاج ترويسة التوكن، وقائمة الوكلاء ثابتة.
- TOSO **لا يفعّل صلاحيات تنفيذ تلقائية** لأي وكيل (مثل `--yolo` أو `--dangerously-skip-permissions`)؛ «الثقة» هنا تخص المجلد فقط. التفاصيل في `SECURITY.md`.
